# 模型与采集器接入交接

供后续 agent 审计和接手使用。此处保存接入决策与验证边界，运行参数以配置和源码为准。

## 接入决策

- 官方 Codex SDK 使用 Scout 专用认证目录，模型由 models.toml 配置。
  专用目录禁止 config.toml，避免继承日常 Codex 的端点、MCP 或其他能力配置。
  修改认证逻辑时保留目录隔离，不使用正式账户注销来构造失败场景。
- 模型请求默认禁用执行和联网能力；知乎搜索词提取例外启用实时搜索及所需宿主。
  此例外用于核实名称和概念，不应扩展到内容评价或偏好归纳。
- 预览的只读保证针对业务 SQLite 和飞书；SDK 仍可能更新专用目录中的认证、缓存和状态。
- 采集器独立管理知乎会话，Scout 通过本机鉴权 HTTP 访问；Cookie 留在采集器会话目录，
  不进入 Scout 配置、模型输入或交接文档。账户导入成功不代表搜索与正文采集已通过。

## 本地产物与脱敏

知乎 CLI 及后台扫描会导出本地运行产物；新流程只导出 schema 5 的单次评价记录。
扫描产物可能包含话题、内容与任务信息，应留在已忽略的本地数据目录，
不得复制到 handoff 或作为仓库验收附件；自定义路径时须检查忽略规则。

- 用户要求验收结束后清理测试任务及其关联数据，包括测试话题、内容快照、候选、
  发送与控制记录、本地运行目录，以及独立采集器的任务、分页游标和证据。
  清理前复核真实反馈及其他任务引用，仅删除本次验收产生的数据。
- 本次用户明确保留群内验收消息；本地发送与授权记录删除后，这些测试卡片不再可操作。
  保留 RSS、真实业务数据、登录态、凭据和配置，不新增测试数据备份、清理报告或永久清理脚本。
- 清理完成后只核对数据库和服务健康，不再为验证清理效果发起新的搜索、模型调用或飞书消息。

交接只保留必要结论。不得保存实际凭据、Cookie、个人偏好与反馈原文、账户与群标识、
消息与任务标识、本机绝对路径或原始模型响应。必要位置使用环境变量名、相对路径或占位符。

## 事实来源与验证边界

接入规则来自精简前 README，并核对了 codex_runtime 和知乎 CLI 的相关入口。
上述接入规则最初整理时未进行登录、模型、采集器或飞书实测，不把旧文档或历史报告当作当前验证证据。
接入变更需验证真实登录、刷新、重启后的认证复用及受影响的模型和采集链路；
涉及投递时完成真实飞书验收，未覆盖场景在回复中说明，不生成独立验收文件。

  程序验证稳定身份、固定字段和结果组合；空偏好不能拒绝相关或存疑内容。
- 偏好在开始时或明确继续请求入库时固定；等待归纳不成为扫描准入条件。
  已完成评价保留其原偏好版本，不因下一次继续切换版本而重算。
- 本次真实搜索成功，但正文返回 HTTP 403；用户确认故障自前一晚持续。
  已停止本次两轮扫描。该故障阻断新内容的完整投递验收，不能以旧正文的模型验证替代。
  已有真实全文的真实端点调用覆盖四类结果，仍未覆盖五条送达、追加、耗尽、反馈归纳和发送恢复闭环。

### 403 定位边界（2026-09-30）

- 本机采集器鉴权正常。用现有会话在隔离浏览器上下文中实测，账户接口返回 200；
  一篇回答和一篇专栏的网页均返回 403，响应包含 `/zse-ck/v4/` 校验脚本。
  同一会话访问对应正文 API 均返回 200，目标身份匹配且未标记截断。
- 同一专栏的普通无头浏览器导航仍返回 403。因此不能将执行页面脚本视为已验证的修复，
  也不能据此断言账户失效或 IP 被全面封禁；网页校验开始触发的具体条件仍未确定。
- 定位时独立采集器的 `Service.details` 先请求网页，仅在网页成功但缺少正文时回退至正文 API。
  网页 403 会直接进入失败分支，导致可用的正文 API 没有被调用；修复因此放在采集器边界。
- 以上结论来自真实只读请求与采集器 SQLite 时间线；诊断未改变正式会话或重启历史任务。

### 正文采集修复与验证（2026-09-30）

- 后续已将详情改为直接请求目标回答或专栏的正文 API，移除网页请求及页面实体提取路径。
  显式请求付费、截断和正常状态字段，正文来源身份必须同时匹配 ID 与类型；保留原有完整性限制。
  上游 403 中的 `/zse-ck/` 脚本现在归入需要验证，沿用暂停与会话保留机制。
- 真实本机采集器重新读取此前失败的两篇回答和两篇专栏，四篇均返回完整正文。
  Scout 实际记录接入、来源身份与原始证据哈希检查通过，证据来源均为目标正文 API。
  此次未遇到真实付费、截断或 API 校验拦截负例，未执行新的模型与飞书投递验收。
- 语法与静态检查通过，采集器已重启加载修复。本次临时任务和证据已清理，
  未建立 Scout 扫描或内容发送记录，保留用户刚清理后的重测起点。

## schema 5 升级与恢复边界（2026-09-30）

- 离线升级入口为 `scripts.upgrade_zhihu_content`。须先停止 listener 及相关后台写入任务；
  脚本同时取得 listener、工作流、扫描、学习及 sender 锁，用 SQLite backup API 备份，
  检查源库、备份与升级后的完整性，完成标记保证重复执行不再次处理新扫描。
- 所有旧扫描仅为历史记录，保留原 JSON 但不解释其阶段；写入永久停止标记，取消旧任务，
  未送达记录设为失败并标注升级原因。普通重试不能释放这些记录；旧卡片继续要求重新搜索。
  内容快照、话题、所有者、反馈、有效偏好与已送达去重记录保留。
- 新流程只恢复 schema 5：完成的 `content` 结果复用，未取得结果的中断调用可重试；
  普通单篇失败跳过，全局模型故障暂停并仅在明确继续后重试对应内容。
- 发送名额既包含持久化队列，也包含已评价通过、暂未取得 sender 锁的内容。
  发送器再次按请求名额检查，计数依据为成功送达；发送 UUID 在恢复时不重建。
- 本次实际完成了数据库备份、完整性及保留数据核对，旧扫描全部停止；新扫描停止操作已落库。
  由于真实知乎正文 HTTP 403，完成内容的恢复复用和发送 UUID 恢复仍缺少新流程端到端证据。

## 重新验收前的数据清理（2026-09-30）

- 用户随后明确要求清理知乎运行数据，并选择保留 RSS、真实反馈与有效偏好。
  此次清理另行删除了此前升级保留的扫描和内容发送去重记录，历史内容可在新搜索中重新参与评价。
- 正文只保留反馈直接依赖的六份快照，供后续偏好学习使用；候选、评价、扫描、问题扩展、
  采集器任务、分页游标和采集记录已清空。保留所有者、话题、配置及升级完成标记。
- 已接收事件的必要去重凭据保留为终态；旧卡片内容、快照关联与消息授权已移除，
  这些凭据不参与内容去重，不能恢复旧扫描或投递。群内历史消息保留。
- 清理时停止相关写入服务并持有现有进程锁，两个 SQLite 库通过 backup API 备份；
  备份与旧运行产物离线保存在 `data/backups/before-zhihu-reset-*`，不参与运行。
  数据库完整性、外键及保留表逐行内容核对通过，清理过程未改动采集器 Cookie 文件。
- 服务恢复后再次核对：采集器登录有效，扫描、采集、内容去重和待发送队列仍为空，
  保留的反馈与有效偏好可正常读取，RSS 数据与备份逐表一致。
- 此次清理没有修复上文的网页 403 回退缺口，也没有执行新的端到端投递验收。

## 搜索排序与卡片精简（2026-10-03）

- 用户确认新查询计划每词先综合、后最新轮转。已冻结任务保持原流顺序与游标，
  不重排索引，否则在途响应与分页恢复可能对应错误的搜索流。
- 正文快照可能以重复标题开头；仅摘录跳过开头的同名独立行，不改全文、快照哈希或模型输入。
- 原文链接之后保留真实反馈及修改入口，删除处理记录、学习进度和搜索控制按钮；
  搜索控制集中在进度卡。进度卡搜索词与模型开销之间不再展示信息，异常状态仍在顶部显示。
- 进度卡模型开销只显示模型设置、调用次数及累计耗时，阶段次数与 token 仍内部记录。
  删除刷新状态和未处理候选入口，复核列表保留返回进度卡的导航；不处理历史卡片或增加旧版本兼容。
- 用户将停止定义为不可恢复的结束；满五篇后的等待仍可继续。停止标记持久化后不得由继续
  清除，排队的继续操作也不能覆盖停止。清理只针对被停止的本轮，不批量处理历史扫描。
- 清理须在扫描线程收尾后持有扫描锁与 sender 锁；未推送候选的正文副本还存在于扫描 JSON
  和操作记录中，不能只删候选表。终态标记与停止进度卡在同一事务提交；压缩后的本地导出
  在提交前写入，文件错误或进程中断时仍能重新执行清理。SQLite 空闲页复用，不在线 VACUUM。
- 已送达与真实反馈依赖的快照保留。发起过 HTTP 但未记录成功的内容按发送结果不明处理，
  仅保留发送身份与关联快照，去掉队列卡片和候选副本；普通重试不能释放它们。
  不能仅凭停止后的 failed 状态认定飞书未收到，故不能自动删除这类快照或重新发送。
- 本节记录用户决策与恢复边界，不作为端到端验收证据，不批量改写历史消息或评价。
