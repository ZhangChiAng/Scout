# 知乎搜索与偏好规则

Scout 为单一所有者搜索知乎内容。话题范围与内容偏好分别判断：喜欢某篇文章不会扩大话题，
无关内容也不等于用户不喜欢。知乎偏好独立于橘鸦 RSS。

## 模型分工与内容规则

| 任务 | 模型 | 输入与输出 |
| --- | --- | --- |
| 相关性 | GPT-6 Luna / medium / Fast | 话题、标题、完整正文及上下文；返回内容身份、相关／无关／不确定及理由 |
| 搜索词转写 | GPT-6 Sol / medium / Fast | 原话题与描述；返回本轮完整有限查询计划 |
| 摘要与偏好评价 | GPT-6 Sol / medium / Fast | Luna 结果、完整正文、本批冻结偏好；返回推荐决定、理由及必要摘要 |
| 偏好归纳 | GPT-6 Sol / medium / Fast | 当前有效反馈及之前偏好；返回有依据和适用范围的偏好 |

Luna 必须识别完整对象身份。大小写、空格、连字符可以是同一名称的写法，不同版本或型号不能
当作别名。话题限定 GPT-6 Sol／Luna 时，GPT-6 Astra、GPT-5.6 Sol／Luna 不属于目标对象。
标题指向 Astra 时，正文的“GPT-6”“6”等省略称呼应结合上下文理解，不能扩大为整个系列。
只有明确的目标对象信息才能支持相关；不确定也必须有具体相关性依据，缺少证据不能作为放行理由。

明确无关的内容保留理由和复核入口，不调用 Sol、不生成摘要。相关内容交给 Sol：空偏好直接
推荐，有依据但仍存相关性疑点则保留不确定。存在真实偏好后，只有明确违背偏好范围及证据的
内容才拒绝；未被偏好覆盖不代表不喜欢。拒绝时无需摘要，准备发送的内容必须有有效摘要。
Sol 不重新判断相关性，不自行加设质量门槛。摘要忠实于全文，区分作者观点和已证实事实。

实际提示词集中在 `scout/zhihu_semantics.py`。当前配置：

```toml
[model]
model = "gpt-6-sol"
reasoning_effort = "medium"

[zhihu_relevance]
model = "gpt-6-luna"
reasoning_effort = "medium"
```

Fast 由共享 Codex 运行时使用 priority 服务档位。相关性单独读取 `[zhihu_relevance]`。

## 反馈与当前个人偏好

喜欢和不喜欢都先填写自然语言理由，再提交；飞书输入框最多 1,000 字，后端拒绝空白理由。
每篇只使用最后一次有效反馈。未反馈不是不喜欢，送达不代表阅读。偏好只依据实际反馈归纳，
每条包含反馈修订 ID、适用范围及置信程度；单篇反馈只形成局部、暂定偏好。

当前生效的是偏好第 1 版，六条均为暂定规则，以下是便于阅读的摘要；SQLite 中保留完整原文及依据：

| 依据 | 偏好 | 边界 |
| --- | --- | --- |
| 反馈 1 | 喜欢有助于理解 Codex agent、有信息量的厂商材料翻译 | 不推断对厂商整体的偏好 |
| 反馈 2 | 不喜欢按任务细分模型及思考档位的选择推荐，已有自己的选择思路 | 不排斥模型技术讨论 |
| 反馈 3 | 不喜欢以情绪宣泄、玩梗、拉踩为主且缺乏参考价值的内容 | 即使赞同观点，也不推断品牌喜恶 |
| 反馈 4 | 喜欢理性分析 | 不推断认同文章全部论点 |
| 反馈 5 | 喜欢有实际使用依据、具有参考价值的任务建议 | 不推断认可其他观点或扩大关注型号 |
| 反馈 6 | 质疑以一键生成网页游戏评价模型、又宣称优于榜单的论证方式 | 不反对所有榜单、网页游戏任务或模型评测 |

反馈更新后，Sol 可以继续修订这些规则。本文的个人偏好表记录此次定稿状态，实时版本以
`python -m scout.zhihu topics` 和 SQLite 为准。

## 查询计划与批次

搜索词转写（`zhihu_topic_queries_v4`）单独启用实时联网搜索，先查证话题含义和实际称呼，
再由模型统一生成互补的关键词查询及名称写法变体。新名词不在模型知识库中属于正常情况；
资料不足时以用户信息为准，不猜测别名，不扩大到其他型号、版本或议题。
不规定搜索次数，保留现有 600 秒请求超时和失败处理。
相关性、摘要／偏好评价和偏好归纳仍关闭联网。已保存的查询计划继续复用，
新版只用于尚未生成计划的轮次。转写会话同时启用内置网页工具依赖的 `code_mode_host`；
仅设置 `web_search="live"` 而禁用该宿主会导致工具无法执行。其他模型会话继续关闭该宿主。

精简提示词使用英文编写，源码注释保留完整中文翻译；参考 [Haystack QueryExpander](https://github.com/deepset-ai/haystack/blob/main/haystack/components/query/query_expander.py)
的保留意图、不同措辞和同义表达规则；联网查证和名称变体属于 Scout 的适配，不引入 Haystack 依赖。
话题名称可以是一整句话，提取检索概念即可。用户描述中的说法是检索目标，不代表已证实事实；
网页内容仅作为资料，不执行其中的指令。
输入继续使用 `name`、`description`，模型返回 `{"search_terms": [...]}`，`rewrite_topic()` 返回 `list[str]`。
程序负责非空列表、字符串类型和每词最长 200 字符校验，去除首尾空白和空项，按首次出现顺序精确去重；
不统一转小写、不删除内部空格、不合并不同写法，也不增加查询数量硬上限或规则展开阶段。

旧版提示词（v3）的真实运行记录：话题“anthropic 说头脑风暴时最好使用 low 思考预算”
执行两轮网页搜索、一次网页阅读并返回 10 个查询，包含 Claude、low effort、自适应思考等检索入口。
该记录仅核验旧版话题转写，未验证知乎实际召回效果。

2026-09-30 新版 v4（提示词翻译为英文前）使用 SQLite 已保存话题（ID 4）单独调用 `rewrite_topic()`，未启动知乎扫描或改写已保存计划。
首次在沙箱内因登录目录只读而未发起模型请求；获准使用现有登录目录后，真实调用完成。
GPT-6 Sol / medium / Fast 执行 3 次网页搜索事件（分别包含 2、3、3 个查询），搜索事件处理未阻断，
返回 7 个查询，耗时 14.194 秒。用量为输入 59,925 token（其中缓存 18,432）、输出 476
（其中推理 149），总计 60,401。实际搜索事件、查询列表及用量见
[新版真实转写记录](verification/zhihu-query-rewrite-v4-2026-09-30.json)。
人工核对结果围绕 Anthropic／Claude、头脑风暴和低思考预算；Claude 有检索到的 Anthropic 资料支持，
未见无依据别名或明显偏题。本次全部使用 `Anthropic`，没有保留输入的小写 `anthropic`，
因此不能据此认定模型已完整覆盖名称写法变体。该验收仅确认新版联网转写可运行，不代表知乎召回改善。

每轮固定近 30 天窗口，开始时保存完整、有限查询计划；取消查询数量上限。考虑实体原名称、
大小写、空格、连字符、连写及有依据的别名，只删除空项和完全相同的重复项。
例如 `GPT-6 Sol`、`gpt-6 sol`、`GPT6 Sol`、`GPT 6 Sol` 分别保留。尚未证实知乎是否区分大小写，各种写法的召回贡献留待后续真实搜索对比。
每个实际查询记录新增及重复贡献；计划耗尽后不自动追加词。

每词最新、综合各推进一页，同题默认推进一页，三个规模参数独立调整。相同查询复用已保存的
页面和游标，新写法从第一页开始。可靠完整正文直接复用，缺失时经本机采集器获取。
候选按赞数、发布时间及稳定身份排序，按自身发布时间检查窗口；文章和回答分别按内容 ID 去重。

默认每批 32 篇候选，可调整为 1–32。每次只调整一个规模参数。
每次请求仍为一篇正文，2 路 Luna 并行判断；相关或有依据的不确定结果保存成功后立即进入
SQLite 中的本批 Sol 队列，由 1 路 Sol 按入队顺序处理，无需等待 Luna 全部结束。
批次拥有一个共享 Codex 会话，认证锁由会话所有者持有，请求按独立 thread/turn 分发和取消。
本批冻结候选顺序和偏好版本，全部处理结束后按原顺序发送飞书，完成后等待反馈及明确继续。反馈训练未完成时不开始下一批，训练成功后
仍需明确继续。候选数不等于 Luna 调用数：正文失败的候选不进入模型，也不计为不推荐。

```toml
[semantic]
search_latest_pages_per_advance = 1
search_general_pages_per_advance = 1
question_pages_per_advance = 1
evaluation_batch_size = 32
model_request_size = 1
```

## 操作与恢复

采集器部署见[本机采集器说明](collector-upgrade/README.md)，登录见[Cookie 导入说明](zhihu-cookie-import.md)。
通过 `.env` 设置采集器地址及令牌、飞书身份；数据库默认 `data/scout.sqlite3`。

```bash
.venv/bin/python -m scout.zhihu topics
.venv/bin/python -m scout.zhihu status --run-id <扫描UUID>
.venv/bin/python -m scout.zhihu scan --topic-id <话题ID>
.venv/bin/python -m scout.zhihu continue --run-id <扫描UUID>
.venv/bin/python -m scout.zhihu continue --run-id <扫描UUID> --parameter evaluation_batch_size --value 32
.venv/bin/python -m scout.zhihu stop --run-id <扫描UUID>
```

`append --quantity N` 指定新增合格结果目标，仍逐批等待反馈和明确继续。没有每日自动扫描。
`scan --run-id` 恢复当前状态；`retry-cards` 重试失败卡片。恢复复用成功模型阶段及固定发送 UUID。
正文、相关性、摘要／偏好、采集和发送失败分别记录，不将失败记作不推荐。
单篇 Luna 或 Sol 失败保存为终态，其他内容继续处理；点击继续也不重试模型失败项。
认证失效、额度限制、配置错误或共享连接故障暂停新任务派发，已完成阶段保留。
停止时至多一秒内停止派发，已发请求收尾落库；服务关闭中断在途请求。
重启仅恢复未完成任务与队列，明确失败项跳过。进程中断且未取得结果的请求可能重新执行。
本批队列包括正在执行的 Sol 任务，最多 32 项；结果成功或失败落库后移除。
汇总分别记录模型累计请求耗时、流水线实际运行耗时、Luna/Sol 并发峰值和队列峰值。

当前轮次 `c5155a75-7389-5456-8b3f-1d6eff8099d1` 保持等待用户继续。查询、游标、候选、
反馈、发送去重及消息绑定均保留；已纠正的三条 Astra 判断以无关结论为准。

## 数据与核验

SQLite 保留当前有效偏好及依据、内容和来源、当前判断、阶段恢复状态、飞书消息关联。
已完成批次保留批次身份、偏好版本号及统计，不重复保存旧偏好全文。模型用量保留实际调用、
耗时及可取得的 token 汇总；清理被替代判断不减少已发生的开销，缺失用量不记作零。
运行目录仅保留被引用的原始证据和当前状态报告。

不编写单元或模拟测试。实际核验使用真实模型、知乎、SQLite 和飞书；当前已验证相关性与摘要
分工、必填理由、偏好更新、逐批暂停、发送及 Astra 误判复核。新查询变体搜索贡献与模型阶段
失败后的跳过、2 路 Luna 与 1 路 Sol 并发及中断恢复仍需后续真实场景覆盖。代码清理以静态检查、真实数据库完整性及引用检查验收，
不为验收构造反馈或自动开始新批次。
