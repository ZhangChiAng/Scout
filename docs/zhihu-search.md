# 知乎主动搜索实验

第一步验证：给定一组关键词，知乎能返回哪些值得进一步阅读的社区内容。
入口为 `python -m scout.zhihu`，每次手动运行，输出可检查的本地报告。
这是一条独立实验入口；`docs/scout-spec.md` 描述的日报入口仍为 `python -m scout`。

## 运行

使用仓库规定的 CPython 3.14 和已锁定依赖。在本地 `.env` 中加入：

```dotenv
ZHIHU_ACCESS_SECRET=替换为知乎开放平台个人中心的AccessSecret
```

凭证也可以由环境变量注入，进程环境优先。不要把真实凭证放进查询文件、命令参数、
报告或 Git 提交。入口只请求知乎官方站内搜索地址，拒绝 HTTP 重定向。

先看精确关键词的原始召回；这一步不调用模型：

```bash
uv run --locked python -m scout.zhihu --query 'DeepSeek'
```

再比较示例中的宽搜和场景查询，并使用 Scout 已配置的模型筛选：

```bash
uv run --locked python -m scout.zhihu \
  --queries-file zhihu-queries.example.txt --evaluate
```

`--evaluate` 使用现有 `models.toml` 和 `SCOUT_LLM_API_KEY`，复用现有 Responses
严格 JSON 契约、超时和推理配置。每批最多六条，默认每轮最多评价三十条。
需要评价更多候选时指定 `--max-evaluations 60`，上限为 120；预算外候选仍然保留。
所有查询及原始返回先落盘，再开始模型调用，便于在模型失败后重放。

查看终端打印的结果目录。修改筛选提示词后可对同一批材料重放，无须重复搜索：

```bash
uv run --locked python -m scout.zhihu \
  --replay data/zhihu-search/本轮目录/search.json --evaluate
```

可用 `--query '词一' --query '词二'` 代替查询文件。`--query`、`--queries-file`、
`--replay` 三者互斥。查询逐字发送，仅去除首尾空白、注释和重复查询；单轮最多
十二条，每条最多 240 字。没有自动扩写、按热度排序或关键词黑名单。

## 如何看效果

每轮写入 `data/zhihu-search/时间-随机标识/`，终端同时输出 Markdown 报告：

| 文件 | 用途 |
| --- | --- |
| `search.json` | 每个查询、请求时间、完整 JSON 返回或请求错误；用于重放。 |
| `candidates.json` | 去重后的候选、命中查询、作者、来源链接及所有不同的返回片段。 |
| `evaluations.json` | 筛选结论、原文依据、失败记录，以及使用的模型名和提示词。 |
| `report.md` | 每条查询的候选与保留数量，以及全部候选、材料和理由。 |

优先用 `ContentType + ContentID` 去重，否则用规范化链接。同一回答由不同查询
命中时合并查询关系，同时保留不同的搜索片段。原始返回里的链接保存在快照中；
报告使用去除查询参数的知乎链接。不同回答不会因为属于同一个问题而被合并。

模型只输出三种结论：**值得展开、折叠、待看原文**。明确保留或折叠必须引用输入
片段，程序检查引文是否确实存在。引文存在不等于结论已经得到独立验证。
全部候选留在报告中，便于检查误杀，比较宽搜与场景查询实际找到了什么。
报告中的“值得展开”数量是模型筛选结果，不是人工验收的准确率。

首轮重点检查三个问题：哪些查询带来新的具体体验；哪些只有泛泛评价或重复内容；
哪些片段不够判断、必须点原文。用这批结果决定下一步是否增加查询、全文读取或
问题追踪。没有拿到真实返回前，不预先建设自动发现作者、定时追踪或反馈学习。

## 返回边界与失败行为

- 当前读取的是 **搜索接口的 `ContentText`**，不保证是完整回答。不补抓图片、
  任意回答正文或完整评论，模型也不能声称看过这些材料。资料不足保持“待看原文”。
- 不将接口 `EditTime` 推断为发布时间；原始值保留在候选记录中。本版不承诺只搜
  最新发布，也不发送未经验证的时间过滤、排序或分页参数。
- 只发送官方公开鉴权示例中已确认的 `Query`；返回数量由服务端决定。若返回
  `HasMore=true`，报告明确提示尚有结果，本版不假装已经遍历全站。
- 每次请求限制为 30 秒、2 MiB；顺序搜索，调用间隔一秒。不自动重试。HTTP
  401/403/429 或业务鉴权、限流错误会停止后续查询，并记录未执行的查询。
- 返回结构不符、部分条目损坏或模型失败都会保留已取得的结果并返回非零退出码。
  空结果仅在接口明确给出空列表或空结果原因时视为成功。
- 单批模型输入超过 100000 字符时明确标为未评价，不静默截断。设置了评价数量
  上限而还有候选未评价时，同样在报告中说明并返回非零退出码。
- 结果目录权限为 0700，文件写完后设为 0600。输出为个人本地材料，按内容使用
  权限保管；不要把完整搜索快照当成可公开再分发的数据集。

## 接口依据与当前验证状态

请求方式与鉴权依据：[知乎数据开放平台](https://developer.zhihu.com/)。
固定请求 `GET /api/v1/content/zhihu_search?Query=...`，使用 Bearer Access Secret
和秒级 `X-Request-Timestamp`。

响应字段适配参考公开客户端的
[原始响应类型](https://github.com/zlZayn/dsh-zhihu-search/blob/05c2f4f0ef6c44e9b5c9ba391a0bd83b28c0a858/src/types.ts)，
采用 `Code / Data / Items / ContentText / Url` 等字段。这是公开实现参考，尚未用
Scout 自己的凭证验证；若服务端契约不同，本入口会保留返回并明确报错。

开发环境只完成语法编译和 CLI 帮助检查，未添加单元测试。当前环境没有知乎或
Scout 模型凭证，也无法直连知乎，因此尚未取得真实搜索样本，未验证召回、筛选
质量或生产端到端运行。首次验收应在实际运行环境执行上述命令，以原始返回为准。
